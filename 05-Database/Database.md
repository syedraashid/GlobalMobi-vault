# Database

Human overview of the TifoXR SQL database. **For the current structure, start at [[DB Current State]]**, which is regenerated by the refresh command ([[DB Refresh Command]]) and carries its own "as of" date and counts. Nothing in this note is generated, so it holds no numbers that could go stale.

## First baseline (historical)
- Built from `dev-06-10-2026-Schema-Only.sql`, an SSMS script kept outside the vault. The file name says 06-10-2026 but its header says **14-10-2026 16:39**; the header date was used. Still unconfirmed which is right.
- Environment: **dev** only. Test and prod have not been checked. Prod may be behind.
- Schema only: no table data. The single `INSERT` in the file is inside a stored procedure for `pending_invitation`.
- At that time: 193 tables, 471 stored procedures, 331 foreign keys, no views, functions or triggers.

## Platform facts (from the script header)
- Azure SQL Database, edition **Basic**, service objective Basic, max size **2 GB**.
- Compatibility level 160 (SQL Server 2022 behaviour). Collation `SQL_Latin1_General_CP1_CI_AS`. Ledger off.
- Access uses **Microsoft Entra** identities (`CREATE USER ... FROM EXTERNAL PROVIDER`): an application identity for dev, a developers group, and three break-glass groups (ReadOnly, DDL, Owner). Individual staff also have named users. No passwords appear in the file. Staff names are not recorded in this vault.

## Findings worth knowing
- **Two hub tables.** `user` is referenced by 43 foreign keys and `space` by 41. Most features hang off these two. Then `media` (17), `currency` (15), `item` (13), `entity` (11).
- **`image_data` has no primary key.** Every other table has one.
- **13 tables have no foreign keys at all** (neither in nor out). See [[DB Table Catalog]]: filter for FK out and FK in both 0.
- **Rewards, Rules Engine and 3D Streaming have no stored procedures.** The backend probably reaches them with EF Core or inline SQL. Not verified; check the repositories.
- **`usp_admin_*` is the biggest procedure family (64).** Likely the CMS and admin side, but this is a guess from the name.
- **Reference data is not in the file.** Lookup tables (statuses, types, currencies, roles) are structure only, so their allowed values are not documented here.
- Several secret-like columns exist as **names only**: `payment_gateway_config.encrypted_secret_key` and `client_secret`. The script holds no values.
